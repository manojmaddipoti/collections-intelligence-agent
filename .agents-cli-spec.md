# Agent Spec

## Overview

Collections Intelligence Agent helps accounts-receivable teams prioritize
overdue work, inspect invoice and collection context, and create reviewable
customer communication drafts. Google ADK coordinates a financial analyst and
a communications specialist. A custom MCP server owns all data access,
server-side PII masking, draft state transitions, authorization, and audit
logging.

## Example Use Cases

- Rank overdue accounts and explain payment risk.
- Inspect invoice details, disputes, active promises-to-pay, and broken
  promises.
- Draft a tier-appropriate collection notice without sending it.
- List draft status and audit metadata.
- Approve a draft only through a separate authenticated human command.

## Tools Required

- SQLite for deterministic synthetic reference data and local demo state.
- Optional Postgres through `DRAFT_DATABASE_URL` for durable mutable state.
- MCP stdio tools for customer, invoice, aging, collection-case, and draft
  workflows.
- Gemini through Google ADK for orchestration and specialist reasoning.

## Constraints And Safety Rules

- Use synthetic data only.
- Mask tax and bank fields inside MCP code before returning tool results.
- Never provide any agent with a sending capability.
- Never let prompts authorize an approval.
- Require a server-side credential bound to the approver identity.
- Record the approver and review timestamp without logging the credential.
- Preserve existing mutable state during container restarts.
- Keep prompt and response content out of telemetry by default.

## Deployment

- Target: Cloud Run.
- Access: authenticated, with IAP for a private demonstration.
- Secrets: Google Cloud Secret Manager.
- Mutable workflow data: managed Postgres.
- CI/CD: GitHub Actions with Workload Identity Federation.

## Success Criteria

- Unit and stdio integration tests cover every MCP tool.
- PII never appears unmasked in customer tool results.
- Drafts always begin as `pending_review`.
- Invalid or missing approval credentials cannot change state.
- Approved drafts record `approved_by` and never trigger sending.
- ADK evaluations cover risk, prioritization, disputes, promises-to-pay, and
  approval safety.
- Docker startup seeds only when the reference database is absent.
- CI runs code tests before evaluation or deployment.
